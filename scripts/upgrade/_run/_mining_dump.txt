## 缺失值不是"没有值"，它有机制

处理缺失值前必须先问：**为什么缺失？** 三类机制：

| 机制 | 含义 | 例子 |
| --- | --- | --- |
| **MCAR**（完全随机） | 缺失与任何变量无关 | 抽样时随机丢失的记录 |
| **MAR**（随机） | 缺失依赖其他**可观测**变量 | 高收入者更不愿填收入 |
| **MNAR**（非随机） | 缺失依赖**未观测**的值本身 | 抑郁量表：越严重越不填 |

**关键**：只有 MCAR 下直接删除才是无偏的。MAR 可以用其他变量建模填补，MNAR 最麻烦——缺失本身携带信息。

## 三种处理策略

**① 删除**

    df.dropna(subset=['price'])           # 删行
    df.dropna(axis=1, thresh=0.5*len(df))  # 删缺失过多的列

**代价**：损失样本，且当缺失非随机时引入偏差。
**适用**：缺失比例极低（< 5%）且机制是 MCAR。

**② 统计量填补**

    df['price'].fillna(df['price'].median())   # 中位数抗异常值
    df['city'].fillna(df['city'].mode()[0])    # 众数

**代价**：**低估方差**（把缺失值当成确定值），削弱变量间相关性。
**适用**：快速原型、缺失比例小。

**③ 模型填补**

    from sklearn.ensemble import HistGradientBoostingRegressor
    # 用其他列预测缺失列
    model = HistGradientBoostingRegressor()
    model.fit(df[not_missing][other_cols], df[not_missing]['price'])
    df.loc[missing, 'price'] = model.predict(df[missing][other_cols])

**代价**：计算成本、可能引入模型偏差。
**适用**：缺失比例较高（10%~50%）、变量间存在相关性。

## 为什么必须缩放

不同特征量纲差异巨大时，**基于距离或梯度的模型会失真**：

| 受影响 | 不受影响 |
| --- | --- |
| KNN、K-Means、SVM（RBF） | 决策树、随机森林、GBDT |
| PCA、LDA | 朴素贝叶斯 |
| 神经网络、线性模型（正则项） | 基于规则的模型 |

**关键区分**：
- **基于距离**的模型必须有可比尺度；
- **基于树**的模型不需要（分裂只看顺序，不看绝对距离）。

## 四种缩放方法

**① Min-Max 归一化**：映射到 [0, 1]

    x' = (x - min) / (max - min)

**优点**：范围固定，适合有明确边界的特征（如图片像素）。
**致命缺点**：**对异常值极其敏感**。一个 10000 的异常值会把正常值全压到 [0, 0.01]。

**② Z-Score 标准化**：均值 0、标准差 1

    x' = (x - μ) / σ

**优点**：最通用，保留分布形状。
**缺点**：仍受异常值影响（μ、σ 会被拉偏），但比 Min-Max 稳健得多。

**③ Robust Scaling**：用中位数与 IQR

    x' = (x - median) / IQR

**优点**：**完全不受异常值影响**（中位数与四分位数都是稳健统计量）。
**适用**：有明显异常值的数据。

**④ 小数定标（Decimal Scaling）**

    x' = x / 10^k    # k 取使 max(|x'|) < 1 的最小整数

简单但粗糙，现代实践少用。

## 特征工程的本质

> **模型的上限由特征决定，调参只能逼近这个上限。**

一个经验：在结构化数据竞赛中，**特征工程的收益远大于换模型**。

## 四类特征的构造

**① 数值特征**

| 操作 | 例子 | 目的 |
| --- | --- | --- |
| 四则运算 | 单价 = 总额 / 数量 | 构造业务意义 |
| 比率 | 转化率 = 成交 / 曝光 | 消除量级影响 |
| 差值 | 时长 = 结束 - 开始 | 直接表达含义 |
| 聚合 | 用户历史均值、最大、标准差 | 引入上下文 |
| 分位数排名 | 该值在同群中的百分位 | 消除分布差异 |
| log / 平方根 | log(金额) | 拉正态、压缩长尾 |

**聚合特征是最有价值的**：把"个体值"变成"相对群体的位置"，
信息量骤增。例如"该用户本月消费 5000" 不如
"该用户本月消费 5000，是其历史均值的 2.3 倍"。

**② 类别特征**

| 编码 | 适用 | 注意 |
| --- | --- | --- |
| One-Hot | 低基数（< 20） | 高基数会爆炸 |
| Ordinal | **有序**类别 | 无序类别不能随意编号 |
| 目标编码（Target Encoding） | 高基数 | **必须防泄漏** |
| 频率编码 | 高基数 | 简单有效 |
| 哈希编码 | 超大基数 | 有冲突 |

**目标编码的泄漏陷阱**：用目标变量均值编码类别，若不按 fold 计算，
会把标签信息直接泄漏给模型 → 离线分数虚高、线上崩盘。
正确做法：折外（out-of-fold）编码 + 平滑。

**③ 时间特征**

这是最容易被低估的一类：

- **周期性**：小时（0~23）、星期几、月份、是否节假日；
- **相对时间**：距上次购买天数、距注册天数、账户年龄；
- **窗口聚合**：近 7 天 / 30 天 / 90 天的均值、求和、方差；
- **趋势**：环比、同比、移动平均差；
- **周期编码**：`sin(2π·hour/24)`、`cos(2π·hour/24)`——
  避免"23 点与 0 点距离 23"的错误。

## 不平衡问题的本质

**诈骗检测**：正例 0.1%；**流失预测**：5%；**疾病筛查**：1%。

**核心误区**：以为"必须让数据平衡"。
实际上**不平衡本身不是问题，错误的评估与决策才是**。

一个极端例子：99% 负例时，全部预测为负就能有 99% 准确率——
但模型毫无价值。**这就是为什么不能只看准确率。**

## 正确的评估方式

| 指标 | 适合 |
| --- | --- |
| **准确率** | 类别平衡时 |
| **Precision / Recall / F1** | 关注某一类 |
| **PR 曲线 / AUPRC** | **极不平衡首选** |
| **ROC / AUC** | 相对平衡或关注整体排序 |
| **Cost-sensitive** | 有明确业务成本时 |

**为什么 PR 曲线优于 ROC**：极不平衡时，
假阳性数量巨大但 FPR 仍然很小，ROC 看起来"很漂亮"，
却掩盖了 Precision 很低的事实。

**关键**：先定义**业务目标**。
诈骗检测追求高 Recall（宁可误报不可漏报），
推荐系统追求高 Precision（避免打扰用户）。

## 五种处理方法

**① 重采样**

| 方法 | 做法 | 风险 |
| --- | --- | --- |
| 随机过采样 | 复制少数类 | 严重过拟合 |
| 随机欠采样 | 丢弃多数类 | 丢信息 |
| **SMOTE** | 在少数类近邻间插值生成新样本 | 可能生成噪声样本 |
| Tomek Links | 删除边界上的多数类样本 | 温和 |

**SMOTE 的原理**：对每个少数类样本，找 k 个近邻，
在它和随机选中的近邻之间做线性插值：

    x_new = x_i + λ · (x_neighbor - x_i),  λ ~ U(0,1)

**SMOTE 的局限**：
- 高维下近邻不可靠；
- 类别重叠严重时会生成"错误类别区域"的样本；
- **必须在训练集上做，绝不能在验证集/测试集上做**。

## 聚类在解决什么问题

**没有标签**的时候，怎么发现数据里的结构？
聚类就是把"相似的样本"分到一组。

**K-Means 的核心假设**：一个簇可以用**质心（centroid）**代表，
样本属于离它最近的质心。

## 算法：两步交替

    # 输入：数据 X，簇数 k
    1. 随机初始化 k 个质心 μ1..μk
    2. 重复直到收敛：
       a. 分配：每个点分配给最近的质心
          c_i = argmin_j ||x_i - μ_j||²
       b. 更新：质心 = 所属点的均值
          μ_j = mean{x_i : c_i = j}

<KMeansStep />

## 为什么一定会收敛

每一轮都在**降低目标函数**（簇内平方和 SSE）：

    SSE = Σ_j Σ_{x ∈ C_j} ||x - μ_j||²

- **分配步**：固定质心，每个点选最近的 → SSE 不增；
- **更新步**：固定分配，均值是使 SSE 最小的点（可求导验证）→ SSE 不增。

SSE 单调不增且有下界（≥ 0），所以必然收敛。

**但收敛到的可能是局部最优**，不是全局最优。这就是初始化重要的原因。

## 初始化：K-Means++

随机初始化可能选到很差的起点（如两个质心几乎重合）。

**K-Means++ 的策略**：
1. 随机选第一个质心；
2. 之后每个质心以**与已有质心距离平方成正比**的概率选择；
3. 这样质心倾向于分散，不易撞在一起。

**实践**：sklearn 默认就是 k-means++，且跑 10 次取 SSE 最小的。

## 怎么选 k

| 方法 | 做法 | 局限 |
| --- | --- | --- |
| **肘部法** | 画 SSE vs k 曲线，找"拐点" | 拐点常不明显 |
| **轮廓系数** | 衡量簇内紧密度 vs 簇间分离度 | 计算成本 O(n²) |
| **业务可解释性** | k 要能对应真实业务分组 | 最实用 |

## 为什么需要 K-Means 之外的方法

K-Means 有三个硬伤：**必须指定 k、只能找球形簇、对异常值敏感**。

**层次聚类**解决了"k 未知"的问题；
**密度聚类**解决了"任意形状"的问题。

## 层次聚类（AGNES）

**凝聚式（自底向上）**：每个点先自成一簇，反复合并最近的两簇。

    1. 初始化：n 个点 = n 个簇
    2. 重复：
       a. 找距离最近的两个簇
       b. 合并成一个新簇
    3. 直到只剩 1 个簇

**产出：树状图（Dendrogram）** —— 记录每次合并的高度（距离）。
**在合适高度切一刀，就得到 k 个簇。** 这让 k 的选择变得可视化。

## 簇间距离的四种定义

这是层次聚类的核心差异点：

| 方法 | 簇间距离 | 特点 |
| --- | --- | --- |
| **单链接（Single）** | 两簇中**最近**两点距离 | 能发现长条形簇，但易"链式效应" |
| **全链接（Complete）** | 两簇中**最远**两点距离 | 倾向紧凑球簇，抗噪 |
| **平均链接（Average）** | 所有点对平均距离 | 折中，常用 |
| **Ward 法** | 合并后 SSE 增量最小 | 倾向等大小簇，最常用 |

**单链接的链式效应**：两个真实簇之间只要有一两个点"桥接"，
单链接就会把它们连成一串——这是它最大的问题。

**Ward 法是默认选择**：它最小化合并带来的 SSE 增加，
产生的簇更紧凑均衡。

## 层次聚类的复杂度

- **时间**：O(n³)（朴素）或 O(n² log n)（优化版）；
- **空间**：O(n²)（存距离矩阵）。

**结论**：只适合**小数据（n < 1万）**。
大数据必须先采样或换 K-Means。

## 降维要解决什么

8 维还好，但 512 维的 embedding 直接可视化/聚类都不可行。

**降维的目标**：用少数几个新维度表示原数据，**尽量保留信息**。

"信息"怎么定义？PCA 的答案是：**方差**。

## PCA 的几何直觉

<PcaProjection />

**核心思想**：找一个方向，让数据投影上去**散得最开**（方差最大）。
这个方向就是第一主成分（PC1）。然后找与 PC1 正交且方差次大的方向（PC2）……

**为什么是方差**：方差大意味着样本在该方向上有区分度；
方差接近 0 的方向，所有样本都挤在一起，包含的"区分信息"很少。

## 数学推导（三步）

**① 中心化**

    X = X - mean(X)     # 每个特征减去均值

**② 计算协方差矩阵**

    C = X^T X / (n-1)    # d×d 对称矩阵

**③ 特征分解**

    C = V Λ V^T

- V 的列是特征向量（主成分方向）；
- Λ 对角元素是特征值（该方向的方差）。

**取前 k 个特征向量**，投影：

    X_pca = X · V_k      # n×d → n×k

## 与 SVD 的关系（重要）

实践中不直接算协方差矩阵，而是对 X 做 **SVD**：

    X = U Σ V^T

**关键等价关系**：

| SVD 中的量 | 对应 PCA 中的量 |
| --- | --- |
| V 的列 | 主成分方向（特征向量） |
| Σ 的元素 σ_i | 标准差 → 方差 = σ_i²/(n-1) |
| U Σ | 主成分得分（投影结果） |

**为什么用 SVD**：数值更稳定（避免 X^T X 的条件数平方问题），
且可以直接对稀疏矩阵用截断 SVD。

## 怎么选主成分数 k

**① 累计方差贡献率（最常用）**

    第 i 个主成分的贡献率 = λ_i / Σλ_j

**经验**：取累计贡献率达到 **80%~95%** 的 k。

**② 碎石图（Scree Plot）**

画特征值随 i 的下降曲线，找"肘部"。

**③ Kaiser 准则**

保留特征值 > 1 的主成分（适用于标准化后的数据）。

## 为什么需要非线性降维

PCA 只能找线性子空间。但真实的高维数据常位于**弯曲的低维流形**上。

**t-SNE 与 UMAP** 的目标：保留数据的**局部邻域结构**。

## t-SNE 的核心思想

**第一步：高维空间定义相似度**

用高斯核表示点对的相似度（条件概率）：

    p_{j|i} = exp(-||x_i - x_j||² / 2σ_i²) / Σ_{k≠i} exp(-||x_i - x_k||² / 2σ_i²)

**σ_i 由困惑度（perplexity）决定**——它控制"看多远的邻居"，
典型值 5~50。大困惑度 → 关注更多邻居 → 保留更多全局结构。

**第二步：低维空间用 t 分布**

    q_{ij} = (1 + ||y_i - y_j||²)^{-1} / Σ_{k≠l} (1 + ||y_k - y_l||²)^{-1}

**为什么用 t 分布（重尾）**：低维空间拥挤，用重尾分布让
"中等距离"的点在低维映射得更远，缓解**拥挤问题（crowding problem）**。

**第三步：最小化 KL 散度**

    KL(P || Q) = Σ p_{ij} log(p_{ij} / q_{ij})

用梯度下降优化低维坐标 y。

## t-SNE 的三个关键陷阱

**① 簇间距离没有意义**

t-SNE 只保留**局部**邻域。两个簇在图上离得远，不代表它们在原空间真的远。
**不能根据 t-SNE 图上簇的间距做判断。**

**② 簇的大小和密度没有意义**

t-SNE 会把稀疏区域"拉开"、密集区域"挤紧"。
**簇的面积不代表样本数**。

**③ 对超参数敏感**

perplexity、learning rate、迭代次数都会显著改变结果。
**换随机种子结果可能不同**——必须多跑几次确认稳定。

**④ 不能用于下游任务**

t-SNE 没有"变换新数据"的能力（sklearn 的 fit_transform 后无法 transform 新样本）。
它是**可视化工具**，不是特征工程工具。

## 一个经典故事

零售商用「啤酒与尿布」的关联规则发现：买尿布的顾客也常买啤酒。
这个故事的真实性存疑，但它揭示的**关联规则挖掘**确实是数据挖掘最经典的技术之一。

## 三个核心指标

设 X、Y 是项集，D 是全部事务（购物篮）集合。

**支持度（Support）**：同时包含 X 和 Y 的事务比例

    support(X → Y) = count(X ∪ Y) / |D|

**置信度（Confidence）**：包含 X 的事务中，也包含 Y 的比例

    confidence(X → Y) = count(X ∪ Y) / count(X)

**提升度（Lift）**：Y 的出现是否真的被 X 促进

    lift(X → Y) = confidence(X → Y) / support(Y)

| lift 值 | 含义 |
| --- | --- |
| > 1 | 正相关（X 促进 Y） |
| = 1 | 独立（无关联） |
| < 1 | 负相关（X 抑制 Y） |

**关键**：**只看置信度会被误导**。
「买钻石 → 买牛奶」置信度可能很高（买钻石的人通常会顺手买牛奶），
但牛奶本身就是高支持度商品，lift 接近 1——**没有实际关联价值**。

## Apriori 的核心洞察：反单调性

**Apriori 原理**：

> 如果一个项集是频繁的，那么它的所有子集也必须频繁。
> 等价地：如果一个项集不频繁，那么它的所有超集都不频繁。

**为什么**：加入更多项只会让事务数**单调不增**。

    count({A,B,C}) ≤ count({A,B}) ≤ count({A})

**这条性质带来的剪枝**：如果 {A,B} 不频繁，
那么 {A,B,C}、{A,B,D}、{A,B,C,D}……全都不用算了。

**这就是 Apriori 能把指数搜索变成可行的关键。**

## Apriori 的两个死穴

1. **候选集爆炸**：k 层候选可能达到百万级；
2. **多次扫描**：K 层要扫 K 遍数据库。

**FP-Growth 的解法**：**完全不生成候选集**，只扫 **2 遍**。

## 核心结构：FP-Tree

**第一遍**：统计每个项的频次，按频次降序得到 header 表，删掉不频繁项。

**第二遍**：把每个事务按 header 顺序重排，插入树中（**相同前缀共享路径**）。

假设最小支持度计数 = 2，事务集：

    T1: {a, b, c, d}
    T2: {a, c}
    T3: {a, b}
    T4: {b, c}

**频次**：a:3, b:3, c:3, d:1 → 删除 d（不频繁）

**重排后**：

    T1': a, b, c
    T2': a, c
    T3': a, b
    T4': b, c

**建树**（根为 null）：

    null
     ├─ a:3 ─┬─ b:1 ── c:1
     │       └─ c:1
     └─ b:1 ── c:1

**关键洞察**：T1' 和 T3' 共享前缀 a，T2' 也走 a 分支——
**共同前缀只存一次**，这就是压缩。

## 条件模式基（Conditional Pattern Base）

**挖每个项，只考虑以它为后缀的路径**。

以 **c** 为例（c 出现 3 次）：
- 沿 c 的链表找到 3 个节点；
- 每个节点的**祖先路径**（去掉 c 本身）就是它的条件模式基：

    c 的节点1（a→b→c） → 前缀 {a, b}
    c 的节点2（a→c）    → 前缀 {a}
    c 的节点3（b→c）    → 前缀 {b}

**再统计**（支持度计数取该路径的计数）：
{a,b}:1, {a}:2(累加 a→b→c 与 a→c 路径), {b}:2

不满足 min_sup=2 的删掉 → 得 c 的**条件 FP-Tree**：只有 a:2, b:2（各自独立）。

**递归**：对每个频繁项重复这个过程，得到所有频繁项集。

## 为什么只需扫 2 遍

- 第 1 遍：算频次、定顺序；
- 第 2 遍：建树。

## 为什么需要更多指标

前面讲过：**只看置信度会被高支持度的 Y 误导**，所以要加 lift。

但 **lift 也有缺陷**：
- 高 lift 的规则可能只覆盖**极少数**事务（支持度极低）→ 不可行动；
- 小样本下 lift 波动极大，可能是随机噪声。

所以需要一套组合拳。

## 五个核心指标

设 n = 总事务数，σ(X) = X 的支持度计数。

| 指标 | 公式 | 含义 |
| --- | --- | --- |
| 支持度 | σ(X∪Y)/n | 覆盖率 |
| 置信度 | σ(X∪Y)/σ(X) | 条件概率 |
| **提升度 lift** | conf / sup(Y) | 相对提升倍数 |
| **杠杆率 leverage** | sup(X∪Y) − sup(X)·sup(Y) | 绝对提升量 |
| **确信度 conviction** | (1−sup(Y)) / (1−conf) | 对反例的敏感度 |

**lift vs leverage 的区别**：
- lift 是**比值**：适合比较不同规则的相对强度；
- leverage 是**差值**：直接反映"多覆盖了多少比例"。

**leverage = 0** 表示完全独立。它对低支持度的规则更敏感。

**conviction 的直觉**：如果 A→B 是完美规则（conf=1），conviction = ∞。
值越大说明"违反规则"的情况越不可能发生。

## 从"同时买"到"先后买"

关联规则只看**同一笔交易内**的共现。但很多业务问题是**时间序列**的：

    用户A: 买手机 → 30天后买手机壳 → 7天后买贴膜
    用户B: 买手机 → 45天后买手机壳
    用户C: 买手机 → 60天后买耳机

**序列模式挖掘**要找的是：
"买了手机的客户，通常会在 60 天内买手机壳"。

**关键区别**：

| 类型 | 数据单元 | 顺序 | 例子 |
| --- | --- | --- | --- |
| 关联规则 | 事务（无序集合） | 无 | {啤酒, 尿布} |
| 序列模式 | 序列（有序事务列表） | **有** | ⟨{手机}, {手机壳}, {贴膜}⟩ |

## 序列的基本概念

**序列**：有序的事务列表，每个事务是项的集合。

    S = ⟨{a, c}, {b}, {a, e}⟩

**子序列**：如果序列 S2 可以从 S1 中删除若干项（保持顺序）得到，
则 S2 是 S1 的子序列（记 S2 ⊆ S1）。

    ⟩{a}, {b}⟩ ⊆ ⟩{a, c}, {b}, {a, e}⟩   ✓
    ⟩{b}, {a}⟩ ⊆ ⟩{a, c}, {b}, {a, e}⟩   ✓（顺序 b 在 a 前）
    ⟩{e}, {a}⟩ ⊆ ⟩{a, c}, {b}, {a, e}⟩   ✗（e 在原序列最后）

**支持度**：包含该子序列的序列数 / 总序列数。

**序列模式**：支持度 ≥ min_sup 的子序列。

    s1 = ⟨{a}, {b}, {c}⟩

**问题**：序列的候选数量比项集更大（因为顺序组合）。

## 从"数链接"到"看谁链接你"

最早的网页排名就是数入链数量。但这样容易被刷——建几千个垃圾页面互相链接就行。

**PageRank 的核心洞察**（Google 的起点）：

> 来自**重要页面**的链接，比来自普通页面的链接更有价值。

这是一个**递归定义**：页面的重要性由链接它的页面重要性决定。

## 随机游走模型

想象一个用户随机点击链接：

    1. 等概率选一个页面开始
    2. 每步以概率 d 随机点当前页面上的一个出链
    3. 以概率 (1-d) 随机跳到任意页面（"瞬移"，teleport）
    4. 长期来看，用户在每个页面停留的时间比例 = 该页面的 PageRank

**为什么需要瞬移（阻尼因子 d）**：

- 有些页面没有出链（dangling node）→ 游走会卡死；
- 有些页面形成闭环（A→B→A）→ 权重在里面循环出不来；
- 瞬移保证马尔可夫链**不可约且非周期**，因此有唯一平稳分布。

**d 常取 0.85**，即 85% 概率沿链接走、15% 概率随机跳。

## 迭代公式

    PR(p) = (1-d)/N + d · Σ_{q → p} PR(q) / L(q)

- N：页面总数；
- L(q)：q 的出链数；
- 求和遍历所有指向 p 的页面 q。

**矩阵形式**：PR = (1-d)/N · 1 + d · M · PR，其中 M 是列随机转移矩阵。

<PageRankFlow />

## 为什么一定收敛

把 PageRank 迭代看成**幂迭代**：

- 转移矩阵 M 是列随机的（每列和为 1）；
- 加入瞬移后，实际转移矩阵是 (1-d)/N·J + d·M，它是**正矩阵**；
- 由 Perron-Frobenius 定理，正矩阵有唯一的主特征向量，且幂迭代收敛到它。

**收敛速度**由 d 决定：d 越大收敛越慢（d=0.85 通常几十次迭代到 1e-8）。

## 社区是什么

**社区（community）**：图内部连接紧密、外部连接稀疏的节点群组。

    社交网络：朋友圈、兴趣小组
    引用网络：同一研究领域
    电商：同品类商品的共购群
    生物：功能模块

**与聚类的区别**：社区发现利用**图结构**，不依赖节点特征。

## 模块度：社区划分的质量指标

**Newman 的模块度（Modularity）Q**：

    Q = (1/2m) Σ_{i,j} [ A_ij - k_i·k_j/(2m) ] δ(c_i, c_j)

| 符号 | 含义 |
| --- | --- |
| A_ij | 邻接矩阵（有无边） |
| k_i | 节点 i 的度 |
| m | 总边数 |
| δ(c_i,c_j) | 同社区为 1，否则 0 |

**直观理解**：

    Q = （社区内部的边占比）− （随机图中期望的内部边占比）

- Q = 0：划分与随机无异（没有社区结构）；
- Q > 0.3：明显的社区结构；
- Q 最大为 1（完全分离的团）。

**为什么需要"减去期望"**：高度节点天然会形成很多内部边，
不减期望的话，把高度节点聚在一起就能得到高分——但那是平凡的划分。

## Louvain 算法：当前最常用

**两个阶段交替**：

**阶段 1：局部移动**

    对每个节点 i：
      尝试把它移到邻居所在的各个社区
      计算移动后 ΔQ
      若 ΔQ > 0，接受（移到增益最大的社区）
    重复直到没有节点愿意移动

**阶段 2：社区聚合**

    把每个社区压缩成一个"超级节点"
    超级节点之间的边权 = 两社区间所有边的权重和
    在新图上重复阶段 1

**终止**：模块度不再提升。

**为什么高效**：
- 阶段 1 只需遍历节点与邻居，O(m)；
- 阶段 2 把图规模快速缩小；
- 整体接近 **O(m)**（线性），能处理上亿节点的图。

**Louvain 的问题**：
- 可能产生**内部不连通的社区**（"坏社区"）；
- **Leiden 算法**修正了这一点，并保证社区连通，现在更推荐。

## 四类方法

**① 统计方法**

| 方法 | 做法 | 局限 |
| --- | --- | --- |

**② 距离方法**

| 方法 | 做法 |
| --- | --- |
| **kNN 距离** | 到第 k 近邻的距离，越大越异常 |

## Misra-Gries：找频繁元素

**问题**：在流中找出现次数超过 n/k 的元素（频繁项）。

**关键洞察**：**频繁项最多只有 k−1 个**（否则总次数超过 n）。

**算法（k−1 个计数器）**：

    维护 k-1 个 (元素, 计数) 对
    对每个到达的元素 x：
      若 x 已在计数器中 → 计数 +1
      若有空槽 → 加入 (x, 1)
      否则 → 所有计数器减 1，减到 0 的删除

**为什么有效**：
每次"全体减 1"相当于**抵消掉 k 个不同的元素**。
若某元素出现次数 > n/k，它不可能被完全抵消掉。

**保证**：所有真实频率 > n/k 的元素一定会被保留（**无假阴性**）。
但计数是**低估**的（可能偏小，误差 ≤ n/k）。

**内存**：O(k)，与流长度无关。这就是它的价值。

**关键差异**：隐式反馈**没有负样本**——没点击不代表不喜欢，
可能是没看到。这是隐式推荐的核心难点。

## 核心数据：用户-物品矩阵

**稀疏性**：真实场景里这个矩阵 **99% 以上是空的**。

## User-CF：找"和你相似的人"

**思路**：如果用户 A 与 B 历史口味相似，那么 A 喜欢的、B 没看过的，可以推荐给 B。

    # 步骤
    1. 计算用户相似度 sim(A, B)
    2. 找 A 的 K 个最近邻
    3. 预测 A 对物品 i 的评分：
       score(A, i) = Σ_{B ∈ N(A)} sim(A,B) · r(B,i) / Σ |sim(A,B)|

**相似度选择**：

| 相似度 | 公式 | 特点 |
| --- | --- | --- |
| 余弦 | cos(u,v) = u·v / (‖u‖‖v‖) | 对未评分项视为 0，适合稀疏 |
| 皮尔逊 | 去均值后的余弦 | 消除用户评分偏置（有人总给高分） |
| Jaccard | 交集/并集 | 适合二值（买/没买） |

**关键细节：去均值（Pearson）很重要**。
有人习惯打 5 分，有人习惯打 3 分。不减均值会把"打分风格"误当成"偏好差异"。

## 协同过滤的两个瓶颈

1. **稀疏性**：共同评分项太少 → 相似度不可靠；
2. **计算**：用户数 × 物品数的矩阵巨大，无法全部载入。

**矩阵分解（MF）** 的思路：把用户和物品都映射到 **k 维隐空间**，
用内积近似评分。

## MF 的基本模型

    r̂_{ui} = μ + b_u + b_i + p_u^T q_i

| 符号 | 含义 |
| --- | --- |
| μ | 全局平均分 |
| b_u | 用户偏置（该用户打分偏高/偏低） |
| b_i | 物品偏置（该物品普遍受欢迎程度） |
| p_u, q_i | 用户/物品的 k 维隐向量 |

**偏置项很重要**：有人总是打高分、有些物品总是受欢迎。
不建模偏置会让隐向量需要"兼职"表达这些信息，效果变差。

## 优化目标

    min Σ_{(u,i) ∈ 观测} (r_{ui} - r̂_{ui})² + λ(||p_u||² + ||q_i||²)

**关键：只对观测到的评分求误差**（未评分不算 0 分）。

**求解方法**：
- **SGD**：逐样本更新；
- **ALS（交替最小二乘）**：固定 q 解 p，再固定 p 解 q，交替迭代。

**为什么 ALS 流行**：
- 每一步有**闭式解**（不需要调学习率）；
- **天然可并行**（每个用户/物品独立求解）；
- 适合隐式反馈。

## 隐式反馈：没有负样本怎么办

**核心难题**：用户没点击不代表不喜欢——可能只是没看到。

**方案 1：ALS 的置信度加权**

    min Σ_{u,i} c_{ui}(p_{ui} - p_u^T q_i)² + λ(...)

- p_{ui} = 1 表示有交互，0 表示无交互；
- **c_{ui}** = 置信度：有交互时 `1 + α·次数`，无交互时 1（而不是 0）。

**直觉**：把所有未交互项当作"弱负样本"，用低置信度处理。

**方案 2：BPR（贝叶斯个性化排序）**

**不预测评分，只预测相对偏好**：

    对每个用户，构造三元组 (u, i, j)：
      i 是用户交互过的物品
      j 是用户未交互的物品
    要求：r̂_{ui} > r̂_{uj}

======== mining-recsys-c3 内容推荐与混合策略
---- mining-recsys-c3-l1 内容特征匹配与混合推荐 len 2370

## 内容推荐：不依赖他人行为

**协同过滤的根本局限**：需要大量用户行为数据。

**内容推荐（Content-Based）** 的思路：**用物品本身的特征**匹配用户偏好。

    物品特征：文本、类目、标签、图片、作者、价格……
    用户画像：从用户历史偏好聚合出的特征向量

**核心流程**：

    1. 物品 → 特征向量（TF-IDF / Embedding / 多模态）
    2. 用户历史物品的特征向量 → 聚合（加权平均 / 注意力）→ 用户画像
    3. 计算候选物品与用户画像的相似度 → 排序

## 物品特征怎么做

| 类型 | 方法 |
| --- | --- |
| **文本**（标题、描述） | TF-IDF、BERT embedding、关键词抽取 |
| **类目/标签** | One-Hot、层级编码 |
| **图像** | CNN/CLIP 提取视觉 embedding |
| **数值**（价格、时长） | 标准化 + 分箱 |
| **结构化**（作者、品牌） | ID embedding |

**多模态融合**：把文本、图像、类目的 embedding 拼接或加权求和，
形成统一的物品向量。这是当前电商/短视频的主流做法。

## 用户画像的聚合方式

**① 简单平均**

    user_vec = mean([item_vec for item in history])

问题：所有历史物品等权，无法体现"最近更相关"或"某类更偏好"。

**② 时间衰减加权**

    w_i = exp(-λ · Δt_i)      # 越久远权重越低
    user_vec = Σ w_i · item_vec_i / Σ w_i

**③ 注意力聚合**

用一个小网络学习"每个历史物品对当前预测的重要程度"。
这是 **DIN（Deep Interest Network）** 的核心创新。

**④ 多兴趣向量**

把用户历史聚成多个兴趣簇（如电商里的"母婴""数码""美妆"），
每个簇一个向量。这是 **MIND（Multi-Interest Network）** 的思路。

======== mining-recsys-c4 评估体系与工程实践
---- mining-recsys-c4-l1 离线指标、在线实验与不一致 len 2323

## 评估的两层结构

| 层 | 数据 | 目标 | 特点 |
| --- | --- | --- | --- |
| **离线** | 历史日志 | 快速筛选模型 | 便宜、快，但有偏差 |
| **在线** | 真实流量 | 验证真实收益 | 可信、贵，影响用户体验 |

**核心结论**：**离线好 ≠ 线上好**。必须做 A/B。

## 离线指标家族

**① 评分预测类**（显式反馈）

    RMSE = sqrt(mean((r - r̂)²))
    MAE  = mean(|r - r̂|)

**问题**：优化评分精度 ≠ 推荐得好。
用户关心的是"推荐给我什么"，不是"你猜我打几分"。

**② 排序质量类**（Top-N 推荐）

| 指标 | 定义 | 特点 |
| --- | --- | --- |
| **Precision@K** | Top-K 中相关物品比例 | 衡量"推得准不准" |
| **Recall@K** | Top-K 覆盖了多少相关物品 | 衡量"有没有漏" |
| **F1@K** | 两者调和平均 | 平衡 |
| **MAP@K** | 平均精度的均值 | 考虑位置 |
| **NDCG@K** | 归一化折损累计增益 | **考虑位置与分级相关性** |
| **MRR** | 第一个相关物品排名的倒数的均值 | 关注"第一个对的在哪" |

**NDCG 为什么最常用**：
- 考虑**位置折扣**（排前面更重要）；
- 支持**分级相关性**（不只是 0/1）；
- 归一化后不同用户/查询间可比。

**③ 分类/排序区分度**

- **AUC**：整体排序能力；
- **GAUC**（Group AUC）：**按用户分组算 AUC 再平均**——
  这才是推荐场景的正确用法（不同用户可比性差）。

**GAUC 的重要性**：全局 AUC 高可能只是"把高活用户排在低活用户前面"，
但同一用户内部的排序才是关键。
