## 1. 意图

为“已经会 Python 变量、循环、函数、文件与异常处理，但从未写过爬虫”的中文学习者，建设一门可以直接在现有网站学习、练习、做项目并接受审计的完整课程。

课程不能停留在“教你用 BeautifulSoup 抓一个网页”的碎片教程。它要建立的是一条完整工程链路：

```text
URL / HTTP → HTML / DOM → 字段抽取 → 链接发现 → Frontier
→ robots.txt / 限速 → 持久化与恢复 → 动态渲染
→ 数据质量 → 增量更新 → 监控 → 合规与安全
```

最终学习者应当能够：

1. 解释浏览器访问网页时实际发生了什么，以及“网页可见”为什么不等于“允许采集”。
2. 独立解析静态 HTML，处理缺失字段、相对链接、编码和简单容错。
3. 设计一个有 Frontier、去重、限速、重试、持久化和断点续抓的单机爬虫。
4. 判断何时需要 Playwright 一类浏览器自动化工具，并写出基于等待条件而不是固定 `sleep` 的采集程序。
5. 对采集结果做字段校验、质量统计、增量变更检测和可观测监控。
6. 识别 robots.txt 的边界、隐私风险、SSRF、恶意 HTML、日志泄漏等合规与安全问题。
7. 完成五个可本地复现的项目，最后一个形成“可恢复、可限速、可监控的增量采集系统”。

课程正文必须是原创教学写作。教材、标准、论文和开源项目用于确认术语、机制与工程事实，不作为可逐段改写的底稿。

## 2. 为什么采用“独立学科 + 一门综合课程”

### 2.1 选定方案

- 新增学科：`crawling` /「网络爬虫」
- 新增课程：`web-crawling` /「网络爬虫：从静态页面到可监控的增量采集系统」
- 课程内部用 12 章、36 个知识点和 5 个项目构成一条连续学习路径
- 不拆成多门系列课，不增加 `seriesId`

### 2.2 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. 并入现有数据工程课程 | 导航改动小 | 会稀释 dbt / Airflow 的数据工程主线；爬虫还需要 HTTP、DOM、浏览器与合规内容 | 放弃 |
| B. 独立学科 + 一门综合课程 | 学科边界清楚；有足够空间容纳工程闭环；未来可在同一学科扩展反爬对抗之外的正向课程 | 需要新增学科、导航例外和一个较大的课程内容包 | **采用** |
| C. 独立学科 + 多门系列课 | 未来容易做“基础 / 框架 / 分布式”分层 | v1 会产生重复基础、空课程和过早的导航复杂度；36 节课已足以形成完整闭环 | 放弃 |

选择 B 的关键原因不是“爬虫内容多”，而是它服务的学习目标与数据工程、数据分析都不同：核心是“如何合法、稳定、可观测地从外部网络获得数据”，不是“数据拿到以后如何建模”。

## 3. 学习者、结果与非目标

### 3.1 学习者画像

- 会 Python 基础语法：变量、列表/字典、循环、函数、文件读写、异常处理。
- 没有写过爬虫。
- 可能能安装第三方包，但不应默认熟悉命令行、HTTP、HTML DOM、数据库事务或浏览器自动化。
- 目标是能独立完成真实但受控的小型采集任务，而不是掌握绕过网站防护的技巧。

### 3.2 学完后的可验证结果

- 能从 URL 与 HTTP 响应解释一次页面请求，而不是只会调用库。
- 能使用标准库解析固定 HTML 样本，也能在本地环境使用 BeautifulSoup / lxml。
- 能在不访问真实网站的条件下完成字段抽取和确定性测试。
- 能画出并实现一个含状态、队列、去重、限速、重试与持久化的采集流水线。
- 能根据页面是 SSR、CSR 还是 JSON API，选择合理采集方式。
- 能定义数据契约、计算质量指标、识别增量变化与删除。
- 能解释至少六种常见安全/合规失败，并给出防护措施。
- 能完成五个项目，最终项目具备断点续抓、速率证据、变更报告与监控报告。

### 3.3 非目标

- 不教 CAPTCHA 绕过、登录/付费墙绕过、指纹伪造、代理池规避封禁。
- 不教对真实个人数据、私密页面、受限数据库或敏感平台的大规模采集。
- 不承诺 36 节课后能建设商用搜索引擎级分布式爬虫。
- 不在浏览器练习环境中伪装运行 `requests`、`Scrapy`、`Playwright` 或真实网络请求。
- 不复制教材、大学讲义、GitHub 仓库或第三方网站的大段内容。
- 不新增运行时第三方依赖，不把课程做成框架 API 手册。

### 3.4 反目标与失败条件

以下任一情况出现，即使“页面能打开”，也视为课程失败：

- 把 `robots.txt` 写成法律授权，或把“公开可见”写成“可任意采集、保存、转售”。
- 用固定 `sleep`、随机 User-Agent、代理轮换作为“工程能力”的主要答案。
- 代码示例依赖真实网站，导致内容随时间失效或测试不稳定。
- 在浏览器可运行练习中声称使用了 Pyodide 未提供的第三方包或真实网络。
- 章节只有术语堆叠，没有前因后果、手算、图示、失败样例和可完成练习。
- 项目只给最终代码，不提供分阶段验收、故障场景和完成证据。
- 为达到题量而批量生成重复、低信息量的选择题。

## 4. 已确认的平台约束

### 4.1 内容模型

现有数据模型是：

```text
Domain → Course → Chapter → Lesson / Exercise
```

关键事实：

- `Chapter` 同时持有 `lessons` 与 `exercises`。
- 每个 `Exercise` 需要 `explanation`，并应设置 `relatedLessonId`。
- `Demo.lang` 只支持 `python | sql | text`。
- 课程内容使用 Markdown，支持 `<Diagram type="..." />`、表格、代码块和公式。
- 单选题答案必须存在于选项中；多选题答案不能为空；填空题必须有 `blanks`；代码题必须有 `tests`。

### 4.2 浏览器执行环境

站内 Pyodide 只预装 `numpy`、`pandas`、`matplotlib`。不能假定以下包可在站内运行：

- `requests`
- `BeautifulSoup`
- `lxml`
- `Scrapy`
- `Selenium`
- `Playwright`

因此：

- 所有站内计分代码题、可运行 Demo 默认只使用 Python 标准库：
  `urllib.parse`、`html.parser`、`re`、`json`、`sqlite3`、`dataclasses`、`collections`、`heapq`、`hashlib`、`datetime`。
- 所有计分任务使用 HTML/JSON/HTTP 字符串或内嵌本地夹具，确定性执行。
- 第三方库代码只出现在普通 Markdown 代码块中，并明确标注“本地环境运行，不在站内判分”。
- 网络行为通过“请求记录器、虚拟时钟、响应对象”模拟；不把浏览器内模拟描述成真实联网。
- 项目 3 的 Playwright 部分不在站内执行，提供本地确定性夹具、运行说明和验收脚本。

### 4.3 内容审计

`scripts/depth-audit.mjs` 的核心门槛：

- 正文至少 3000 字符；本课程目标为 4000–6000 字符，项目课允许 5000–8000 字符。
- 教学模块需覆盖：学习目标、前置知识、问题背景、直觉理解、核心概念、原理详解、推导/逐步计算、案例、代码实践、图示、常见误区、知识关联、总结、参考资料。
- 至少一个实际图示标签、一个 Demo 或代码块、三条 `tips`，并在章内配足练习。
- 内容或标题出现“推导、公式、概率、统计、风险”等词时，必须有明确公式或逐步数值计算。
- 内容或标题涉及代码/算法时，必须有代码块；涉及结构/流程时应有图示。

`scripts/exercise-rules.mjs` 的题量约束：

| 知识点难度 | 目标题量 |
| --- | --- |
| 1 | 6 |
| 2 | 8 |
| 3 | 10 |
| 4 | 13 |
| 5 | 16 |

审计按“章内习题数 ÷ 章内知识点数”估算练习覆盖，因此每章总题量必须达标，不能只在章末堆题。

## 6. 课程总览与学习弧

课程按五个阶段推进：

1. **看得懂**（1–3 章）：网页不是“页面文本”，而是一次请求、一个 HTTP 响应、一棵 DOM 树和一组抽取规则。
2. **抓得到**（4–6 章）：从单个 HTML 样本扩展到链接发现、Frontier、去重、robots.txt 与限速。
3. **抓得稳**（7–8 章）：引入状态机、持久化、断点续抓，以及 JS 渲染页面的判断与浏览器自动化。
4. **管得好**（9–10 章）：数据契约、质量指标、存储血缘、条件请求、近似重复与重抓调度。
5. **跑得久且负责**（11–12 章）：多 worker、集中去重、故障恢复、监控，以及合规、安全与毕业项目。

每个阶段都先建立“预测 → 失败 → 机制 → 再实践”的节奏，而不是先给最终框架。

## 7. 12 章 / 36 个知识点

### 第 1 章：从网页到数据——爬虫是什么

**章节目标**：建立浏览器、HTTP、HTML、DOM、抽取器之间的正确心智模型，完成第一次纯离线解析，并知道采集的边界。

**预计时间**：4 小时
**题量**：24（8 + 8 + 8）

1. `web-crawling-c01-l01` **网页、浏览器与数据采集：建立正确心智模型**（难度 2 · 8 题）
   - 能区分“服务器返回的 HTML”“浏览器渲染出的页面”“结构化数据”“信息抽取结果”。
   - 能画出 URL → DNS → 连接 → HTTP 请求 → 响应 → HTML → DOM → 字段的数据流。
   - 首先判断 API、公开数据下载、静态 HTML、浏览器渲染四条路径，而不是默认写爬虫。
   - 视觉：`crawl-http-journey`；案例：同一个商品页在 API、HTML、渲染后 DOM 中的三种形态。

2. `web-crawling-c01-l02` **第一个离线解析实验：从 HTML 字符串到结构化数据**（难度 2 · 8 题）
   - 用一段固定 HTML 模拟图书列表，借助 `html.parser` 提取标题、价格、详情链接。
   - 先手写扫描，再引入“结构定位 → 字段映射 → 规范化 → 校验”的抽取流程。
   - 使用 worked example → 半成品 → 独立练习的淡出结构。
   - 视觉：`crawl-dom-tree` 的高亮变体；代码：纯标准库、可站内运行。

3. `web-crawling-c01-l03` **能抓什么、不该抓什么：范围、伦理与法律边界**（难度 2 · 8 题）
   - 使用“授权来源、服务条款、robots.txt、个人数据、保留期限、再分发、请求影响”七问检查表。
   - 明确 `robots.txt` 是自愿排除协议，不是法律授权或许可证。
   - 用加权风险矩阵做一次数值化案例，但不把分数包装成法律结论。
   - 视觉：`crawl-compliance`；案例：公开目录、登录数据、他人个人主页、含个人信息的评论区的对比。

**章节产出**：一张端到端请求/抽取图、一个离线 HTML 解析器、一份可解释的采集边界判断。

### 第 2 章：HTTP、URL 与网络请求

**章节目标**：能读懂一次请求的全过程，使用 URL 和 HTTP 语义定位故障，理解会话、编码、超时与重试。

**预计时间**：6 小时
**题量**：28（8 + 10 + 10）

1. `web-crawling-c02-l01` **URL 解剖与请求生命周期**（难度 2 · 8 题）
   - scheme、host、port、path、query、fragment 的含义；fragment 为什么通常不发给服务器。
   - 百分号编码、IDN、相对 URL、`urljoin`、查询参数顺序。
   - DNS → TCP/TLS → HTTP → 响应 → 渲染/解析，区分失败发生在哪一层。
   - 视觉：`crawl-http-journey`；代码：`urllib.parse` 站点可运行实验。

2. `web-crawling-c02-l02` **HTTP 报文、状态码与响应头**（难度 3 · 10 题）
   - 方法、请求头、状态码家族、`Content-Type`、`Content-Length`、`Location`、缓存头。
   - 403、404、410、429、500/502/503 的区别与重试边界。
   - 用原始 HTTP 文本和“本地响应对象”比较字段，不访问外网。
   - 视觉：状态码决策图 + 典型报文表；代码：解析结构化响应头。

3. `web-crawling-c02-l03` **会话、编码、超时与重试**（难度 3 · 10 题）
   - Cookie、连接复用与会话状态；只保留完成任务所需的最小状态。
   - 如何从 `Content-Type`、meta charset、字节前缀判断编码；不能假设 UTF-8 永远正确。
   - 连接/读取超时、指数退避、抖动、`Retry-After`、幂等与重试预算。
   - 公式：`wait_n = min(cap, base × 2^n) × jitter`，并手算三次重试。
   - 视觉：退避时间轴；代码：虚拟时钟与重试策略，不真实等待。

**章节产出**：URL 诊断表、HTTP 错误决策表、一个可测试的重试策略。

### 第 3 章：HTML、DOM 与页面结构

**章节目标**：从“看页面”转向“看结构”，能用多种定位方式稳定抽取字段，并处理常见的 HTML 容错问题。

**预计时间**：6 小时
**题量**：28（8 + 10 + 10）

1. `web-crawling-c03-l01` **DOM 树：网页结构的骨架**（难度 2 · 8 题）
   - Element、Text、Attribute；父子、兄弟、后代、祖先关系。
   - HTML5 容错解析：未闭合标签、隐式补全、重复属性、注释与脚本。
   - 从扁平字符串走向树结构，理解“选择器实际上在遍历什么”。
   - 视觉：可点击的 `crawl-dom-tree`；代码：`html.parser` 维护元素栈。

2. `web-crawling-c03-l02` **CSS 选择器与 XPath：定位目标字段**（难度 3 · 10 题）
   - 类、ID、属性、后代/子元素、`:nth-of-type` 等常见选择器；XPath 的路径与谓词。
   - 选择器稳定性：优先语义属性，避免深层位置链和一次性随机 class。
   - BeautifulSoup / lxml 示例作为“本地代码阅读”，站内练习用标准库实现迷你定位器。
   - 视觉：同一 DOM 上高亮不同 selector 路径；案例：分类页与详情页字段差异。

3. `web-crawling-c03-l03` **结构化数据、表格与容错解析**（难度 3 · 10 题）
   - JSON-LD、Microdata、Open Graph、HTML 表格与重复卡片。
   - 缺失字段、空白字段、多值字段、`<base>`、相对链接、嵌套表格。
   - 用 schema 和默认值显式表达“不知道”，不伪造数据。
   - 视觉：结构化来源对照表；案例：同一商品来自 JSON-LD 与 HTML 卡片时的冲突合并。

**章节产出**：字段到选择器的映射表、可重复运行的 HTML 解析器、容错案例清单。

### 第 4 章：静态页面抽取

### 第 5 章：链接发现、URL 规范化与 Frontier

**章节目标**：从“抓一个页面”升级为“按规则访问一小组页面”，理解 URL 等价、队列顺序和去重。

**预计时间**：5 小时
**题量**：28（8 + 10 + 10）

1. `web-crawling-c05-l01` **链接发现与 URL 规范化**（难度 2 · 8 题）
   - 解析 `<a href>`、`<base>`、相对 URL；只接受允许的 scheme / host / path。
   - 统一 host 大小写、默认端口、空路径、点段、fragment 与已知追踪参数。
   - 规范化不等于“随便删 query”；错误规范化会造成漏抓或抓错。
   - 视觉：`crawl-canonicalize` 前后对照；代码：标准库 URL 规范化与一组边界样例。

2. `web-crawling-c05-l02` **Frontier：BFS、优先级队列与抓取顺序**（难度 3 · 10 题）
   - Frontier 保存“待访问 URL + 深度 + 优先级 + 来源 + 重试次数”。
   - BFS 的公平性、优先队列的目标导向、访问集合的职责。
   - 用 `collections.deque` 与 `heapq` 手写，用小型站点模拟访问顺序。
   - 公式：重复率、有效页面率与队列增长；手算 20 个 URL 的处理序列。
   - 视觉：`crawl-frontier`；代码：纯 Python 可站内运行。

3. `web-crawling-c05-l03` **抓取陷阱、去重与深度控制**（难度 3 · 10 题）
   - 日历翻页、会话 ID、无限排序参数、重复内容、软 404、镜像路径。
   - 规则：最大深度、最大页面数、允许路径、同 host 限制、异常停止条件。
   - Bloom filter 的“可能见过 / 一定没见过”语义与假阳性，不把它当精确去重。
   - 视觉：`crawl-bloom`；案例：一个带无限日历和追踪参数的合成站点。

**章节产出**：URL 规范化函数、Frontier 数据结构、抓取边界配置与停止条件。

### 第 6 章：robots.txt、礼貌抓取与限速

**章节目标**：理解 robots.txt 的真实定位，能给爬虫加上“有界、礼貌、可解释”的发送策略。

**预计时间**：6 小时
**题量**：28（8 + 10 + 10）

1. `web-crawling-c06-l01` **robots.txt 的正确定位：协议不是法律授权**（难度 2 · 8 题）
   - RFC 9309 的路径匹配、最长匹配、`Allow` / `Disallow`、User-Agent 分组与抓取规则。
   - robots.txt 是自愿排除协议，不等于版权许可、隐私授权或可以忽略服务条款。
   - 用合成 robots 文件与请求路径做判定树，覆盖通配符、最长匹配和未知组。
   - 视觉：`crawl-robots`；代码：小型规则匹配器，不依赖第三方库。

2. `web-crawling-c06-l02` **限速、并发与 token bucket**（难度 3 · 10 题）
   - 请求速率、并发数、队列延迟、每 host 配额与总配额的区别。
   - token bucket：容量、补充速率、等待时间与突发上限。
   - 公式：`wait = max(0, (1 - tokens) / refill_rate)`，手算三个请求的等待。
   - 视觉：`crawl-rate-limit` 时间轴；代码：虚拟时钟下的 token bucket。

3. `web-crawling-c06-l03` **退避、重试与可观测性**（难度 3 · 10 题）
   - 临时错误与永久错误的分类；429/503 与 `Retry-After`；幂等标记。
   - 指数退避 + jitter、最大尝试次数、熔断与停止条件。
   - 指标：请求数、成功率、重试率、限速等待时长、每 host 延迟。
   - 公式：请求成功率、有效吞吐与重试放大系数；给出实际数值案例。
   - 视觉：退避与指标面板示意图；案例：一个只会盲目重试的爬虫如何放大故障。

**章节产出**：robots 解释器、限速器、重试策略和基础指标表。

### 第 10 章：增量采集与变更检测

**章节目标**：从“重复全量抓取”升级为“只抓需要抓的、能识别变化、能处理删除”。

**预计时间**：6 小时
**题量**：28（8 + 10 + 10）

1. `web-crawling-c10-l01` **条件请求：ETag 与 Last-Modified**（难度 2 · 8 题）
   - `ETag`、`If-None-Match`、`Last-Modified`、`If-Modified-Since` 与 304。
   - 304 不等于“页面永远不变”；验证器可能缺失、出错或过于宽松。
   - 条件请求如何减少带宽、服务器压力与重复处理。
   - 视觉：条件请求时序图；代码：本地响应对象模拟 200/304。

2. `web-crawling-c10-l02` **内容哈希、SimHash 与近似重复**（难度 3 · 10 题）
   - SHA-256 识别完全重复；规范化文本与空白/跟踪参数会改变指纹。
   - shingling、64 位 SimHash、Hamming 距离与阈值。
   - 公式：`distance(a,b) = popcount(a XOR b)`；手算一个小样本并解释阈值误判。
   - 视觉：`crawl-bloom` 的位向量变体 + 相似度表；代码：纯 Python SimHash。

3. `web-crawling-c10-l03` **重抓调度、删除检测与版本记录**（难度 3 · 10 题）
   - 变更频率、重要度、新鲜度、抓取预算与重抓间隔。
   - 比较“上次内容哈希 / 当前内容哈希”和 404/410/内容消失；用 tombstone 记录删除。
   - 版本表保存变更前后摘要与提取器版本，不无限保存完整正文。
   - 公式：按抓取价值和预期变化率计算优先级；数值示例说明预算取舍。
   - 视觉：`crawl-recrawl` 状态机；案例：价格变化、标题微调、页面删除和 404 假象。

**章节产出**：条件请求流程、内容指纹、重抓策略、变更/删除报告。

### 8.4 练习设计规则

- 习题 ID 使用 `web-crawling-cNN-lNN-eNN`，例如 `web-crawling-c01-l01-e01`；题号在知识点内稳定、不随排序重排。
- 每个知识点至少有一道“解释为什么”的题，不只考 API 名称。
- 每章至少一道 URL/HTTP/HTML 调试题、一道边界/失败题、一道合规或安全判断题。
- 代码题必须有可执行的 `tests`；测试输入使用内嵌 HTML、JSON 或本地数据结构。
- 代码题只允许标准库；若题面出现 `requests`、`Scrapy`、`Playwright`，必须明确标记“本地说明题”，并使用单选、简答或静态代码分析，不进行站内运行判分。
- 每题必须写 `explanation`，解释错误路径而不仅是公布答案。
- 选择、填空、代码题均设置 `relatedLessonId`，支持做错后回跳。
- 项目课题目拆成可独立验证的子任务；项目整体用验收表、rubric 和演示证据评估，不用单个代码题假装覆盖整个项目。
- 题面不得包含真实个人主页、真实账号、真实受限接口或可执行攻击指令。

### 8.5 防止“题量注水”

每个知识点出题前先写四类“证据点”：

1. 能否解释一个机制？
2. 能否识别一个边界或反例？
3. 能否在固定输入上完成一次实现？
4. 能否把知识迁移到新的、但仍然安全的本地场景？

若一个知识点找不到四个真实证据点，优先调整章节内容，而不是复制近似题。

## 9. 教学法与统一正文模板

### 9.1 每个知识点的固定标题

为了既满足审计，又让学习者形成可预测的阅读节奏，统一使用：

1. `## 学习目标`
2. `## 前置知识`
3. `## 问题背景`
4. `## 直觉理解`
5. `## 核心概念与原理详解`
6. `## 逐步推导与计算`
7. `## 图示与机制图解`
8. `## 完整案例`
9. `## 代码实践`
10. `## 常见误区与安全风险`
11. `## 与其他知识点的关联`
12. `## 本节总结`
13. `## 参考资料与延伸阅读`
14. `## 动手实验`

正文不得以“API 大全”开头。先让学习者预测会发生什么，再展示失败，再引出机制，最后给出可验证实现。

### 9.2 每个知识点的教学节奏

1. **预测**：先问“如果直接这样做，哪一步会坏？”
2. **可视化**：用一个链路、树、队列、时间轴或状态机承载直觉。
3. **完整示范**：给出一个短小但完整的 worked example。
4. **半成品**：挖去关键步骤，让学习者补全。
5. **独立练习**：改变页面结构或故障条件。
6. **迁移**：把机制应用到另一类本地页面或项目阶段。
7. **自我解释**：至少两个“为什么这样设计”“如果删掉这一步会怎样”的提示。

### 9.3 工作示例淡出

对每种核心程序结构（HTML 遍历、URL 规范化、队列、状态机、条件请求），采用：

```text
完整示例 → 填空式半成品 → 独立实现 → 新情境迁移
```

项目课不再给出可直接复制的整份最终答案；只给 starter code、接口、测试和里程碑。学习者在每个里程碑获得可判定反馈。

### 9.4 检索练习与间隔复习

- 每章开头用 3–5 个不判分的检索问题回看上章核心概念。
- 每个知识点至少一个“先关掉页面，用自己的话解释”的问题。
- 关键术语（URL 规范化、Frontier、幂等、ETag、SimHash、SSRF）在后续章节再次出现，并要求辨析而不是重新定义。
- 不宣称某种间隔或“最佳题量”适用于所有学习者；课程说明只承诺按这些机制设计，具体节奏允许调整。

### 9.5 正文、Demo 与代码块

- 每个知识点至少一个视觉锚点（图示或结构化对照表）。
- 每个知识点至少一个可阅读代码块；可在站内运行的放入 `demos`。
- 每个知识点至少三条 `tips`，覆盖易错点、工程或安全注释。
- 所有第三方库代码在代码块标题或正文中标注：“本地环境示例，站内不联网、不判分”。
- 代码输出、请求记录和失败样本必须可复现，不编造运行结果。

### 9.6 参考资料写法

每个知识点末尾 2–5 条，按以下格式：

```text
- [教材/标准/论文/工程文档] 作者或机构，《标题》，版本或日期，链接
- 本段用它支持：某个具体概念、定义或工程事实
```

课程层面的来源矩阵见第 12 节；知识点只引用与当前内容直接相关的一小部分。

## 10. 五个项目

### 10.1 共同规格

五个项目统一采用以下结构，避免每个项目变成不同风格的教程：

1. 场景与不做什么
2. 输入夹具与数据边界
3. 功能要求
4. 架构图
5. 文件布局
6. Starter code 与接口
7. 四个左右里程碑
8. 验收测试
9. 故障排查表
10. Definition of Done
11. 评分 rubric
12. 拓展目标

所有夹具都是合成的、无真实个人信息的本地文件或本地服务器响应。项目可以展示真实第三方库的写法，但站内判分和 CI 不依赖外部网络。

### 10.2 P1：本地静态目录采集器

**位置**：第 4 章第 3 个知识点
**场景**：一个本地合成书店目录，1 个列表页链接到 6 个详情页。
**输入**：固定 HTML 文件、一个含坏链接的列表页、价格缺失/重复卡片/嵌套标签等异常样本。
**目标产物**：

- 抽取 `title`、`price`、`availability`、`source_url`。
- 处理相对链接、重复 URL、缺失字段与坏 HTML。
- 输出稳定排序的 JSONL、CSV 与错误报告。
- 输出记录数、有效数、跳过数与原因统计。

**架构**：

```text
list.html → 发现详情链接 → 详情解析 → 规范化/校验
→ 去重 → JSONL/CSV → 统计报告
```

**建议布局**：

```text
project-01-static/
  starter.py
  fixtures/
    list.html
    detail-01.html ... detail-06.html
  expected/
    records.jsonl
    report.json
  tests/
    test_extract.py
    test_pipeline.py
```

**里程碑**：

1. 解析一个详情页。
2. 发现并连接列表页到详情页。
3. 规范化、去重、缺失值处理。
4. 输出、错误报告、回归测试。

**验收**：

- 期望记录完全匹配；排序稳定。
- 至少 3 个异常样本被正确分类，而不是静默丢失。
- 重新运行产生相同输出。
- 无网络访问；测试命令可在离线环境通过。

**Rubric 重点**：解析正确性 30%、边界容错 25%、输出契约 20%、测试与可读性 15%、报告 10%。

**拓展**：增加一个第二列表页或按价格排序的详情页，但不能改变主验收标准。

### 10.3 P2：分页 JSON/API 采集器

**位置**：第 7 章第 3 个知识点
**场景**：本地 `catalog` API 用游标分页；每页 3 条；第 3 页确定性返回 503；重试后可继续。
**输入**：本地服务器响应、固定 `Retry-After`、一条重复记录、一个格式错误的 JSON 条目。
**目标产物**：

- 读取分页、游标和 `has_more`。
- 超时、重试、有限退避和失败记录。
- 去重与幂等写入 SQLite。
- 中断后从检查点恢复。
- 输出请求次数、成功页数、跳过数和最终记录数。

**架构**：

```text
API 页 → 请求策略 → JSON 解码 → 记录校验
→ UPSERT → checkpoint → 失败队列 → 恢复运行
```

**验收**：

- 首次运行在第 3 页按注入故障中止。
- 第二次运行只补未完成页，最终数据与无故障基线一致。
- 重复运行不产生重复记录。
- 重试不超过上限，且 `Retry-After` 被遵守（使用虚拟时钟）。
- 不访问真实 API。

**Rubric 重点**：分页正确性 20%、恢复语义 25%、幂等 20%、失败处理 15%、报告与测试 20%。

**拓展**：增加“游标失效需从头分页”的本地模式，并解释为什么不能默认适合所有 API。

### 10.4 P3：动态页面采集器

**位置**：第 8 章第 3 个知识点
**场景**：本地动态商品页在 300ms 后渲染首屏，滚动 3 次加载 3 批条目；每一批都由可观察的 DOM 属性标记。
**输入**：本地静态服务器、确定性脚本、可切换的“慢加载”模式。
**目标产物**：

- 用 Playwright Python 启动本地页。
- 使用稳定的 locator 与等待条件，不用固定 `sleep`。
- 处理懒加载与有限无限滚动；达到停止条件后退出。
- 记录每批出现条件、条目数量和失败原因。
- 截图或少量的调试证据不是最终数据来源。

**验收**：

- 所有目标条目只出现一次，顺序稳定。
- 没有固定 `sleep`；等待条件可解释。
- 页面延迟增加时测试仍能通过或给出明确超时诊断。
- 不在站内运行 Playwright，不访问外部站点。

**Rubric 重点**：等待策略 30%、滚动/终止条件 25%、数据完整性 20%、稳定性 15%、记录 10%。

**拓展**：增加资源拦截或两阶段加载，但不能以绕过访问控制为目标。

### 10.5 P4：礼貌型聚焦爬虫

**位置**：第 11 章第 3 个知识点
**场景**：3 个本地 origin（不同端口）组成的小型文档站，每个 origin 有 robots.txt、分页、重复链接、429 和临时错误。
**目标产物**：

- Frontier 与规范化。
- robots.txt 规则判断。
- 每 origin 限速；全局并发上限。
- 允许路径与最大深度/页面数。
- SQLite/JSONL 持久化、任务租约或模拟队列、失败重试。
- 运行指标：请求数、跳过数、重复率、成功率、每 host 等待时间。

**架构**：

```text
seed URLs → canonicalize → robots check → frontier
→ per-host token bucket → fetch → parse → validate
→ SQLite/JSONL → metrics/report → retry/dead-letter
```

**验收**：

- 不允许越界的 origin/path 被请求。
- 每个 origin 的请求间隔满足配置的虚拟时间限制。
- 注入 429 和 503 后不突破重试上限。
- 重复链接只处理一次；重启后不重复已完成记录。
- 指标来自真实运行记录而非手写常量。

**Rubric 重点**：规范/范围 20%、礼貌抓取 25%、队列与持久化 20%、恢复 15%、指标与测试 20%。

**拓展**：加入优先级策略（例如先抓文档索引，再抓深层详情），解释其对公平性的影响。

### 10.6 P5：增量采集毕业项目

**位置**：第 12 章第 3 个知识点
**场景**：本地站点有三份快照（T1/T2/T3），页面既有 ETag/Last-Modified，也有只在正文变化、删除或重新出现的页面。
**输入**：带验证器的响应、无验证器页面、近似重复正文、schema 不合规记录、404/410、429。
**目标产物**：

- 条件请求与内容哈希结合。
- 记录版本、变更摘要、删除 tombstone。
- schema 校验与质量报告。
- 重抓优先级与预算。
- 失败恢复、监控报告和一页设计说明。

**架构**：

```text
snapshot scheduler → conditional fetch → parse/validate
→ content fingerprint → compare previous version
→ version/tombstone → change report → metrics dashboard
```

**验收**：

- T2 准确识别新增、修改、未变、删除四类。
- 304 页面不被错误计为删除或重新抓取正文。
- 只有正文细微变化的页面被 SimHash 或规范化哈希识别为近似重复。
- 失败后重跑不会重复生成版本。
- 报告包含可复核的数字和测试证据。
- 设计说明明确访问范围、数据最小化与保留策略。

**Rubric 重点**：变更检测 25%、版本与删除语义 20%、质量/隐私 15%、恢复与监控 15%、测试 15%、设计说明 10%。

**最终展示**：5 分钟口头/文档演示，说明一个页面从 T1 到 T3 的完整生命周期，以及一次故障恢复。

**拓展**：用本地文本接口替代客户端渲染，比较两种架构的采集成本和稳定性。

### 12.5 开源项目导读路线

开源项目用于“看成熟工程如何划分职责”，而不是让初学者直接照搬框架。每处导读都要求学习者在读完后回到课程自己的极简实现，说明一个相同点和一个不同点。

| 开源项目 | 读什么 | 对应章节 | 课程自己的产出 |
| --- | --- | --- | --- |
| Scrapy | Engine、Scheduler、Downloader、Spider、Item Pipeline 的职责边界；Selector 与 AutoThrottle 文档 | 3、4、6、7 | 标准库抽取器、状态机、限速器；一张与 Scrapy 架构的对照表 |
| Playwright for Python | locator、auto-waiting、浏览器 context 生命周期、等待与超时文档 | 8 | 一个本地动态页夹具与等待条件明确的采集脚本 |
| Crawlee for Python | request queue、storage、并发与失败请求的概念 | 7、11 | 内存队列 + SQLite 检查点；worker 崩溃恢复演示 |

导读顺序：

1. 先让学习者写出可工作的最小实现。
2. 再读开源项目文档中的架构图与接口边界。
3. 用一张“相同点 / 不同点 / 取舍”表比较。
4. 最后只迁移一个明确收益，不把整个框架塞进教学项目。

## 16. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 36 节 × 4000+ 字导致内容生产量过大 | 质量下降或长期无法交付 | 分 7 个波次；先完成第 1 章样板；每波次审核后才继续 |
| 349 题导致重复注水 | 练习无迁移价值 | 每节先写证据点；项目课拆成小任务；以代码/案例题为主 |
| 第三方包不能站内运行 | 示例与实际脱节 | 站内标准库离线；第三方代码明确标注本地环境；项目验收独立 |
| 动态页面测试不稳定 | 学习者无法复现 | 固定本地夹具、确定性延迟、虚拟时间、等待条件测试 |
| 真实站点变化或封禁 | 内容失效 | 不使用真实站点做判分；真实网络只作为不在 CI 的可选观察 |
| robots/法律内容被误读 | 教学风险 | 明确不是法律意见；强调 ToS、隐私、版权和授权；使用合成案例 |
| 图解只在代码里合法、页面不渲染 | 学习者看不到 | 两处注册 + 自动扫描 + 浏览器抽查 |
| 引入第三方代码片段引发许可问题 | 发布风险 | 默认不复制；必要时单独审查许可证、固定版本、注明来源 |
| 新增学科导致导航回归 | 侧栏/移动导航异常 | 更新 `test:nav` 预期；加入单课程学科例外；桌面与移动检查 |
