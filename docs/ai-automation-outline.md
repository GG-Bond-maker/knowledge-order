# 「AI 自动化」课程大纲（第二阶段成果）

> 定位：**软件与业务流程自动化**
> 规模：5 门子课程 / 20 章
> 学员起点：**无 LLM 基础**（M1 需从零讲 LLM）
> 内容原则：详细全面但不枯燥、图文解释性强、交互丝滑
> 题量规则：随知识点难度变化（见附录 A）
> 来源标注：学术来源 / 工程实践（非学术）/ 原创示例 —— 三者必须区分

---

## 总览

| 子课程 | 章数 | 定位 | 学员收获 |
| --- | --- | --- | --- |
| **M1 AI 自动化基础** | 4 | 从零建立 LLM 与自动化的认知 | 知道什么能自动化、LLM 能做什么不能做什么 |
| **M2 Agent 架构与工作流** | 5 | 核心技术 | 能设计并实现一个可靠的 Agent |
| **M3 业务流程自动化** | 4 | 差异化价值 | 能把 AI 接进真实业务流程 |
| **M4 代码与文档自动化** | 4 | 高价值场景 | 能做代码生成、测试、文档处理的自动化 |
| **M5 评估、安全与运维** | 3 | 生产化 | 能评估、监控、保护一个上线的自动化系统 |

## M1 AI 自动化基础（4 章）

> 目标：学员**没有任何 LLM 基础**。这一门课要同时完成"讲清 LLM 是什么"和"讲清自动化能做什么"。

### M1-c1 自动化与 AI：边界在哪里

**学习目标**
- 理解自动化的三个层次：规则驱动 → 数据驱动 → 智能驱动
- 判断一个任务"是否适合自动化"
- 知道 AI 自动化的能力边界与失效模式

**核心概念**
- 自动化的成本结构：开发成本 vs 运行成本 vs 维护成本
- 确定性 vs 概率性系统（这是 AI 自动化与传统的根本区别）
- 长尾问题：为什么 95% 准确率在业务上可能不可用
- 人机协作的四种模式：全自动 / 人工确认 / 人机接力 / AI 辅助

**先修**：无
**难度**：2

**知识点关系**
```
自动化层次 → 确定性/概率性 → 能力边界 → 人机协作模式
```

**来源**
- 原创框架（基于工程实践总结）
- 参考 MIT 6.034 Lecture 1（AI 的定义与范围）

---

### M1-c2 LLM 是什么：从 token 到回答

**学习目标**
- 理解 token、上下文窗口、生成过程
- 知道为什么 LLM 会"幻觉"
- 理解 temperature 等采样参数对自动化任务的影响

**核心概念**
- Token：文本的最小单位（中文约 1 字 = 1~2 token）
- 自回归生成：一次一个 token
- 上下文窗口：模型"短期记忆"的上限
- 概率采样：temperature / top-p 如何影响输出稳定性
- 幻觉的根源：模型在"续写"而非"查询事实"

**先修**：无
**难度**：2

**知识点关系**
```
token → 自回归生成 → 上下文窗口 → 采样参数 → 幻觉与不确定性
```

**图示需求**
- `TokenFlow`：一句话如何被切成 token（可交互输入）
- `AutoregressiveDemo`：逐 token 生成的动画
- `TemperatureSlider`：调温度看概率分布变化

**来源**
- 学术：Chain-of-Thought 论文（理解推理能力）
- 工程实践：OpenAI/Anthropic 官方文档关于 token 与采样的说明
- 原创示例

**先修**：M1-c2

### M1-c4 从脚本到 Agent：自动化的演进

**学习目标**
- 理解"工作流"与"Agent"的本质区别
- 知道什么时候不该用 Agent
- 建立后续 4 门课的路线图认知

**核心概念**
- 三种自动化形态：脚本（确定性）→ 工作流（预定义路径）→ Agent（模型自主决策）
- 成本与可靠性：越自主越贵、越不可控
- Anthropic 的核心建议：**先找最简方案**
- 本课程的路线：基础 → Agent → 业务 → 场景 → 生产

**先修**：M1-c1, c3
**难度**：3

**图示需求**
- `AutomationSpectrum`：三种形态的连续谱（确定性↔自主性）
- `DecisionTree`：该用什么方案的决策树

**来源**
- 工程实践：Anthropic《Building effective agents》（已抓全文）

## M2 Agent 架构与工作流（5 章）

> 目标：这是全课程的技术核心。学完能自己设计并实现一个可靠的 Agent。

### M2-c1 ReAct 循环：推理与行动交替

**学习目标**
- 理解 ReAct 的三段式：Thought → Action → Observation
- 能手写一个最小 ReAct 循环
- 知道 ReAct 为什么会"卡住"以及如何退出

**核心概念**
- ReAct = Reasoning + Acting 交替
- 轨迹（trajectory）：完整的思考-行动-观察序列
- 停止条件：任务完成 / 达到最大轮次 / 检测到循环
- 与纯 CoT 的区别：CoT 只思考，ReAct 会行动并观察结果

**先修**：M1-c3
**难度**：3

**图示需求**
- `ReactLoop`：循环动画（Thought→Action→Observation 转圈）
- `TrajectoryView`：一条真实轨迹的时序图

**来源**
- 学术：ReAct 论文 [2210.03629](https://arxiv.org/abs/2210.03629)
- 学术：Berkeley CS294 第 2 讲（Shunyu Yao 亲讲）
- 原创实现与习题

## M3 业务流程自动化（4 章）

> 目标：把 AI 接进真实业务流程。这是本课程区别于"AI 教程"的差异化价值。

### M3-c1 RPA 基础：从录屏到代码

**学习目标**
- 理解 RPA 的本质（模拟人在界面上的操作）
- 区分录屏式 RPA 与代码式 RPA
- 知道 RPA 的脆弱性来源

**核心概念**
- RPA = Robotic Process Automation，模拟 UI 操作
- 选择器（selector）与元素定位：为什么界面一改就崩
- 录屏式（UiPath/Power Automate）vs 代码式（Playwright/Selenium）
- RPA 的适用边界：稳定的、重复的、规则明确的

**先修**：M1-c1
**难度**：3

**图示需求**
- `RpaLayers`：RPA 的分层（界面层/逻辑层/数据层）
- `SelectorFragility`：选择器失效的示意

**来源**
- 工程实践：UiPath 文档（已验证可访问）
- 原创示例与对比分析

**先修**：M3-c1
**难度**：4

**来源**

### M3-c3 工作流平台：可视化编排的取舍

- 掌握权限隔离的设计
- 知道什么时候必须人工介入

**核心概念**
- 提示注入：工具返回的内容可能包含恶意指令
- 防御：指令与数据隔离、输出过滤、最小权限
- 权限隔离：沙箱、白名单、审批流
- 人工检查点：高风险操作必须确认
- 红队测试：主动找漏洞

**先修**：M5-c2
**难度**：5

**图示需求**
- `InjectionAttack`：注入攻击的示意
- `DefenseLayers`：纵深防御层次图

**来源**
- 学术：CMU 11-766 第 17 讲"Attacking LLMs"
- 学术：Berkeley CS294 第 12 讲"Safe & Trustworthy AI Agents"
- 工程实践：Anthropic/OpenAI 安全指南
- 原创示例
